# Small-buffer audio robustness audit — 3 October 2026

Reported regression: Mackie ASIO at 32 samples worked around Alpha 39; Alpha 42 has audible delay and repeated cut-outs. The actual output endpoint, sample rate, patch and driver timing have not been captured. The cause remains unconfirmed. Keep the 32-sample setting for comparison.

## Version comparison

Between the Alpha 39 commit and Alpha 42, native/Audio is unchanged. Packaged GuitarNam.dll, GuitarEffects.dll and all NAudio/WebView dependencies have identical SHA-256 hashes. Native changes concern TONE3000 category selection. That fix can replace a circuit processor with an actual downloaded capture, so compare the same exported patch, rather than assuming a similarly named device is the same processor. Interface/layout work can also increase system workload despite unchanged DSP.

At 48 kHz a 32-frame callback has 0.667 ms; at 44.1 kHz 0.726 ms, and at 96 kHz 0.333 ms. These are processing deadlines, not measured round-trip latency.

## Verification and remaining qualification

New offline checks hold the control monitor while rendering, exercise 100 concurrent replacements/updates and disposal at 44.1/48/96 kHz and 32/64/128 frames, and alternate 10,000 complementary two-device gain scenes to detect mixed publication. Existing scene/tail, bypass, native effects, capture and replacement-failure tests remain required.

Offline concurrency success establishes resource lifetime and publication behaviour; it does not reproduce a Mackie driver deadline. Hardware comparison must use the same patch, driver, rate, 32-sample buffer and direct output in Alpha 39 and the candidate. Play with the board idle, editor open, parameter edits, scene changes and resizing, with backing off then on. Record load/overruns, driver reset messages and output dropouts. An audio-loopback measurement is needed to quantify latency. No live ASIO listening has been performed in this session.

Further work in priority order: measure full callback/output timing and arrival jitter; remove legacy EQ update allocations; qualify changed native setters; replace separate-output locking with a bounded single-producer/single-consumer transport; benchmark graph preparation/graphics under realistic system load. Avoid silently increasing buffers to hide missed deadlines.

## Supplied patch investigation — 3 October 2026

The supplied Desktop/FreeRig patch.json selects scene index 3: gate → Fortin TS9 NAM → Hendrix 1959JMH NAM → EchoKing → V30 IR → Dragon Room → output. Gate, both captures, delay and cabinet are on; Dragon Room is bypassed. All referenced assets exist locally. The original export/assets remain untouched.

The user clarified Windows audio was tested at the assistant request and then reverted, while the fault persisted. Historical log entries cannot establish the current route or explain the ongoing fault. Existing audio-diagnostics.log records direct ASIO output on 30 September and early 2 October. Later 2 October and recent 3 October starts instead use BIG KNOB STUDIO+ 1-2 as a separate Windows playback endpoint with Mackie ASIO input. Repeated ASIO reset faults are recorded around that change and again on 3 October. The route adds Windows buffering/clock correction; simultaneous routes through the same hardware may also contend, but the log does not establish the cause of the driver resets. Restore Same ASIO interface for a controlled low-delay comparison, with audio stopped first. Current observed running executable was releases/FreeRig-alpha-42/FreeRig.exe; it cannot establish which executable produced the user's earlier reported 256% peak.

Added --profile-patch <export.json> <asset-directory>: warmed synthetic guitar/silence, six seconds measured at 48 kHz and 32/64/128 frames, whole graph plus final output and separate serial-stage timing. It opens no audio hardware, writes patch-performance-audit.txt beside the executable, and leaves the export/assets unchanged. It currently accepts only complete serial chains and uses the saved scene. Rates/models requiring other rates are not silently converted. Stopwatch timing includes OS pre-emption and managed/native work; it cannot distinguish scheduling pauses from DSP spikes. Stage runs are separate, so their percentiles cannot be added.

First candidate 32-frame run: median 23.8%, p99 50.6%, max 247.6%, one missed deadline in 9,000 blocks. Recompiled Alpha 39 engine with the identical profiler/dependencies: median 24.1%, p99 40.7%, max 84.2%, no misses in that 32-frame run. This is an uncontrolled single-run scheduling comparison, not proof of a version regression. TS9 and amp each cost roughly 10% median; bypassed Dragon Room roughly 1%. Later runs produced large isolated spikes even in 64-frame cases; no sustained overload was reproduced offline.

Confirmed managed allocation: .NET Framework's Enumerable.SequenceEqual array enumerators in legacy amp/cab EQ checks allocate 256 bytes per complete supplied-patch block, including unchanged EQ. The measured seven-second loop (warm-up included) allocated 2,688,000 bytes at 32 frames. Replaced that comparison with an indexed double.Equals loop, preserving length/NaN/equality semantics and DSP arithmetic. The same full loop subsequently allocated zero bytes at all three sizes. The pre-fix measured allocation run recorded no gen0 collections; do not attribute its spikes to GC from this evidence. Actual coefficient edits still allocate filters/arrays and remain a follow-up.

Post-fix 32-frame run: median 24.5%, p99 43.9%, max 82.1%, no misses in 9,000 whole-chain blocks. Separate cabinet stage run still had an isolated 358% spike, and whole-chain 64-frame run had a 274% spike: zero managed allocation does not guarantee deadlines. Before/after results are retained under releases/diagnostics (local, ignored). Added zero-allocation steady amp/cab render/output tests at 32/64/128 frames. No live Mackie listening or round-trip measurement performed.
